# PaperScrape v4.8

Two ways your customised themes could quietly lose what you had done to them, both fixed.

## "Reset to default" reset the wrong theme

Every per-theme edit you make lives in one scratch space, tagged with the theme it belongs to. That
tag follows the theme you last **edited** — selecting a different theme in the gallery does not move
it, and it was never meant to.

Every control on the customisation screens knew that and named the theme it was editing. The reset
buttons did not. So tapping **"Reset Houses to default"** — or **"Reset decorations to defaults"** on
the Seasons screen — as the first thing you did after switching themes hit the *previous* theme's
settings instead of the one on screen. Two things went wrong at once, and they hid each other: the
theme you were looking at was not reset (the button seemed to do nothing), and a theme you had not
touched lost that category for good.

Concretely: set Winter's houses to 22%, set Christmas's to 40%, go back to Winter and reset its
houses. Winter stayed at 22%, and Christmas silently dropped to the default 65%.

The reset buttons now name the theme they are resetting, exactly like every other control beside
them. The theme on screen is reset, whatever was last edited is left alone, and no other category on
either theme is touched — including when the theme's settings were saved earlier rather than being
the ones under live edit.

## The night pedestrian density followed you between themes

The **Night density** slider under People is per-theme, like everything else on those screens. It was
missing from the one routine that clears per-theme settings, so it survived every place that routine
is used: switching themes, "Reset this theme's scene to defaults", and restoring a backup.

The visible effect was a value appearing where you never set one. Put Christmas's night density at
19%, then change any unrelated setting on a theme you had never customised, and that theme was now
also at 19%. "Reset this theme's scene to defaults" left the slider where you had dragged it, and a
restored backup carried the old value into the first theme you edited afterwards.

It is now cleared with the rest of the per-theme settings, in all three cases.

## Nothing else changed

No rendering code was touched, and no scene, sprite or colour is drawn differently than in v4.7 —
this release changes only how settings are stored and reset. Your existing themes, saved themes and
backups are read exactly as before: no setting was renamed, moved or dropped, and backup files made
with earlier versions import unchanged.

Four regression tests were added to the theme-persistence suite, comparing whole customisations
rather than single values, so neither defect can come back unnoticed.
