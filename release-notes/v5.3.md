# v5.3

**A small release. One crash fixed, a slightly smaller download, and one thing worth knowing
before you update.** Nothing on screen changed: the wallpaper draws exactly the picture v5.2 drew.

- **A damaged backup file no longer closes the app.** Restoring a backup starts by reading the
  file and showing you what is in it before anything is written. If one of the four scene colours
  in that file had been damaged — a colour stored as text instead of a number — the reading step
  gave up in a way nothing was expecting, and the app simply closed. No warning, no message, and
  it happened at the worst possible moment: while you were trying to get your own settings back.

  Nobody had to do anything malicious for this: a file that got truncated in transfer or mangled
  by a cloud sync was enough. The four colours are now read the same forgiving way as the dozen
  colours beside them, which was always the intention — if a value is unreadable, that one value
  falls back to its default and the rest of the backup restores normally. A file that is damaged
  beyond use still gets what it always got: a plain "this file could not be read" message.

- **This version no longer installs on Intel-based devices, and that is deliberate.** The app used
  to carry its drawing code compiled for four kinds of processor. Two of those — `x86` and
  `x86_64` — are used by emulators and by a small number of Intel-based Android devices,
  **including Chromebooks running Android apps**. They are no longer included.

  If you run PaperScrape on an ordinary Android phone or tablet, this changes nothing for you:
  practically all of them are ARM, and those two builds were dead weight in every download. If you
  run it on a Chromebook or an emulator, **v5.3 will not install, and v5.2 is the last version that
  does.** It keeps working; it just stops receiving updates. This was a deliberate choice, not an
  oversight, so it is written here rather than left to be discovered.

- **The download is about 65 KB smaller** (2 665 676 bytes against 2 732 518 — a 2.4 % cut), which
  is the direct consequence of the two builds above being dropped.

**Under the hood**, with nothing for you to do: every one of the project's 49 outstanding security
advisories was closed by actually updating the build tooling, the app now declares outright that it
refuses unencrypted connections, and two new automatic checks were added — one that throws tens of
thousands of damaged files at the backup reader on every build, which is the check that would have
caught the crash above, and one that inspects the finished app itself.

Nothing you have set is affected. Your themes, colours, sliders and saved themes are exactly as you
left them, and there are no new settings.
