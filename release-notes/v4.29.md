# v4.29

**Nothing in this release changes what you see.** No artwork moved, no scene is drawn differently,
no setting was added, removed or renumbered, and no saved theme is touched. Every reference frame
the test suite holds is byte-identical to v4.28's — which is the point: this release is about how
the wallpaper uses your phone's graphics memory, and it is meant to be invisible.

- **The wallpaper stops running out of texture space.** PaperScrape packs its drawings into one
  shared texture on the GPU, because a scene that has to keep switching textures costs far more
  work per frame. That shared texture was being packed in rows, and the leftover space at the end
  of each row — and above every drawing shorter than the one beside it — was simply abandoned. It
  added up to more than half the space.

  The effect was easiest to see by leaving the wallpaper running and letting it move through
  themes, which is exactly what the daily and shuffle theme settings do: **with nothing switched
  on and no slider touched, the shared texture filled up at the fifth theme**, and from then on
  every new drawing the wallpaper met had to be given a texture of its own — the thing the shared
  one exists to avoid. By the end of a run through all twelve themes, day and night, 25 drawings
  had been pushed out; with every category turned on and every density at maximum, 34.

  It now packs the space properly, and **nothing is pushed out at all** — in either case.

- **Two memory limits that were being read as one.** The project has long had a self-check on how
  much memory its drawings take, and it was being used to argue about the GPU, which it was never
  measuring: the copies that go to the GPU are sized by how big a drawing appears on screen, not by
  how big the file is. Those two numbers do not even move in the same direction. There are now two
  checks, each measuring the thing it is named after, so future decisions about artwork are argued
  against the right one.

- **Several comments in the code that had quietly stopped being true.** Three of them were the
  stated justification for a setting, and two argued the opposite of what measurement now shows. A
  fourth had been reported as stale nine releases ago and never removed. They have been
  re-measured rather than re-typed, and the check that is supposed to catch this class of mistake
  was reading a hand-written list of two files — it now reads the whole source tree.

**If you are wondering what to look for: nothing.** A theme you have been running should look
exactly as it did, and the improvement is that the wallpaper needs less of your phone to draw it.
