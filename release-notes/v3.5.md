# v3.5

**A test fix. The app is identical to v3.4.**

No new features, no behaviour changes, and not a line of the wallpaper, the settings or the scene.
Nothing you can see is different.

---

## What this release is

One of PaperScrape's own automated tests was wrong, and it failed the v3.4 build.

The test starts four background threads and counts how many of them run. What it did not do was wait
for them: it checked the count while some were still starting up, so on a busy machine it could see
three where it expected four and report a failure that was its own doing. That is what happened in
the v3.4 build, and it stopped the release.

The test now waits for the threads it starts before counting them. Nothing was made more lenient —
no retry, no pause, no relaxed threshold, and nothing was switched off. The thing the test is
actually there to check is unchanged and still checked.

## Also confirmed

The on-device test job is separate from the release path and was verified to be so: it cannot block
a release by failing, and a release does not wait for it to finish. That was already the case; v3.5
only writes it down as a project rule so it stays that way.
