# v3.6

**Less work per frame, one correctness fix you will never see, and a build job that was only ever
failing on itself.**

Nothing on screen changes. Every one of the app's committed reference frames still matches exactly.

---

## The wallpaper does less work for the same picture

The scene is painted with a handful of colour gradients: the sky, the hill layer and the glow around
the sun or moon. Until now PaperScrape built those gradients again from scratch for **every single
frame** — around ninety of them a second — even though the wallpaper needs exactly three and they
only change when the light does, which is at most once a minute.

They are now built once and reused. Measured on an Android 17 device: over sixty frames the app used
to create 180 gradient objects, and now creates 3. Over three hundred frames of scrolling, 900
became 3.

This is a battery and CPU change, not a visual one. It is deliberately small and deliberately
measured: the picture is identical, and that is checked by rendering all seventeen of the app's
reference frames and comparing them pixel by pixel.

## Sunrise and sunset can no longer be half-updated

When PaperScrape works out where you are, it stores three things together: today's sunrise, today's
sunset, and whether it has a real position at all. It stored them as three separate values, and the
part of the app that draws the scene reads them from a different thread than the part that writes
them.

That left a gap. If a new position arrived at the wrong instant, a frame could be drawn with the new
sunrise and the *old* sunset — a day length belonging to no place at all. In a test that reproduces
it exactly, a position moving from Florence to Reykjavík produced a 14-hour day, where the two real
answers are 9.5 and 20.5 hours. Day length drives the whole day/night blend, so this reaches the
colour of the sky and the position of the sun.

The three values are now stored as one, and updated as one. A frame gets the whole of the old day or
the whole of the new one, and never a mixture.

If you have never seen a strange sky after your phone found a new location, that is expected: the
window is narrow and it takes a fresh position landing on exactly the wrong millisecond. It is fixed
regardless.

## The on-device build job has been retired

PaperScrape's automated build used to try to start an Android emulator and run the visual tests on
it. In practice it failed every single time it ran, always for a reason that had nothing to do with
PaperScrape — a missing toolchain package, a device that was not ready to install an app yet, and
finally a syntax error inside the emulator tool itself. On the last attempt it also hung while
trying to collect the diagnostics that were supposed to explain the failure.

It has been removed. **The tests themselves have not been touched** — all twenty-four of them,
including every visual reference frame, still exist and are still run against a real device before
each release. What has gone is a build step that had never once reported anything true about this
app.
